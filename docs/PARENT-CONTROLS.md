# Quiet YouTube parent controls

The Omarchy panel and CLI manage one background service. The service owns the parent password hash and settings; Chromium reads managed policy generated by that service. Removing the panel does not stop the service or remove browser policy.

## Install the release

Extract `quiet-youtube-omarchy.tar.gz`, open the extracted directory, and run:

```sh
python packaging/install-user.py
```

This adds the top-right Quiet YouTube icon and `~/.local/bin/quiet-youtube`. It does not activate browser restrictions. The package has a standard Omarchy plugin manifest. This repository includes a compiled extension and can also be installed directly with `omarchy plugin add https://github.com/Drmedkit/quiet-youtube.git --enable`. The Git route gets its system-wide CLI when you install the system component.

Open the panel and choose **Install parent controls**. Administrator authentication installs the root-owned service and prepares a signed extension for Chromium. Then choose a parent password or PIN of at least six characters, repeat it, and click **Set password and enable**. Initial setup also requires administrator authentication so a child cannot claim an unconfigured installation. **This applies managed rules to every Chromium profile on the computer.** Until channels are approved, no channels are allowed.

The release requires Omarchy's Quickshell plugin API, Python 3.10+, OpenSSL, systemd, polkit, and Chromium. It does not need Node or npm on the receiving computer. The installer supports `--browser chrome` and `--browser brave`; those browsers still need manual compatibility testing. The panel installer defaults to Chromium.

After activation, restart Chromium once and refresh any existing YouTube tabs. The earlier unpacked browser prototype is a separate installation: remove it from `chrome://extensions` and from your Chromium startup extension list when migrating. For an administrator-driven migration, pass its ID as `--replace-extension ID` to the system installer; the managed policy blocks that older copy.

## Parent password and agents

Unlock the panel to approve/remove channels, adjust settings, pause/resume protection, or change the password. Unlocking lasts 15 minutes, including when you dismiss and reopen the menu. The **Close** button ends the parent session early. Pausing keeps the extension installed and managed; it only releases YouTube filtering.

To let an agent work, unlock the panel and select **Allow agent / CLI access**. This explicitly writes a short-lived token into your account's private runtime directory. The agent can then run CLI commands without seeing the password. The grant ends no later than the panel session's original 15-minute deadline, even if the panel closes. Run `quiet-youtube lock` to revoke it sooner. Any process running as that same Linux user can use a granted CLI session, so grant access only while you are managing the settings.

You can alternatively unlock from a terminal:

```sh
quiet-youtube unlock
quiet-youtube channels add @kurzgesagt --json
quiet-youtube channels list --json
quiet-youtube settings set hideShorts true --json
quiet-youtube settings set homeFeed subscriptions --json
quiet-youtube status --json
quiet-youtube lock
```

The terminal prompts privately for the password. Scripts can use `--password-stdin` with a trusted secret source. Never put passwords in command arguments, environment variables, chat, version control, or agent logs. JSON responses have `ok` and `data`, or `ok: false` with an error code/message. Failed commands return a nonzero exit code. Read commands do not require a password.

Other commands:

```sh
quiet-youtube channels remove UCxxxxxxxxxxxxxxxxxxxxxx --json
quiet-youtube protection off --json
quiet-youtube protection on --json
quiet-youtube config export rules.json
quiet-youtube config import rules.json --json
quiet-youtube password
```

Exports contain rules only, never password hashes or session tokens. Imported configurations replace the rules and require an unlocked session; they do not change the password or pause state. Channel additions resolve stable IDs from public YouTube metadata.

## Service and deployment

- `/usr/local/lib/quiet-youtube/`: root-owned service and CLI implementation.
- `/var/lib/quiet-youtube/`: private state, salted scrypt password hash, guessing limits, and device-local signing key; directory mode `0700`.
- `/run/quiet-youtube/control.sock`: local Unix socket. Mutations require an expiring token bound to the caller's Linux UID, verified using kernel peer credentials.
- `/usr/local/share/quiet-youtube/`: signed CRX3, local update manifest, installation metadata.
- `/etc/chromium/policies/managed/quiet-youtube.json`: this package's managed policy file; other policy files are not edited.
- `quiet-youtube.service`: starts at boot and restarts on failure. It does not depend on the menu remaining installed or open.

The first five failed password attempts trigger a one-minute wait. Repeated failed groups increase the delay up to fifteen minutes; restarting the service does not reset the limit. Password changes revoke every session. Passwords and tokens are never put into subprocess arguments or service logs.

Each device generates its own extension signing key, so there is no private signing key in the shared release. Updates on that device reuse its key and extension ID. Chromium force-installs the signed package from a local `file:` update manifest; an internet update server or Chrome Web Store listing is not required for this Linux installation. The managed policy prevents removing/disabling this extension through normal browser controls, disables browser developer mode/devtools, and disables guest/incognito/add-profile entry points. It does not block unrelated extensions globally.

`status.policyWritten` means that the on-disk policy matches the requested rules. It is not a browser acknowledgement. Policy changes are asynchronous; verify `chrome://policy`, the managed extension, and actual YouTube behavior on a new child computer. Browser policy files are machine-wide. Conflicting policies from another administrator must be resolved before deploying.

## Update, recovery, removal

For a Git installation, run `omarchy plugin update kids.quiet-youtube`, then open `~/.config/omarchy/plugins/kids.quiet-youtube` in a terminal. For an archive installation, extract a new release, rerun the user installer, and open its directory. In either case run the system installer with administrator authentication:

```sh
pkexec ./packaging/install-system.py --browser chromium
```

Use the same browser selection as the original installation. The password, channel list, and signing key are retained. Browser versions must increase in each extension release. Refresh YouTube tabs after an update. Removing the menu alone never removes the system service.

If the parent password is forgotten, an administrator can reset it from a terminal without knowing it:

```sh
sudo /usr/local/lib/quiet-youtube/quiet-youtube password --reset
```

For full removal, run `pkexec ./packaging/install-system.py --uninstall`, then `omarchy plugin remove kids.quiet-youtube --yes`. The system uninstaller retains `/var/lib/quiet-youtube` for recovery; an administrator can delete that directory explicitly if the signing key and settings are no longer needed. Remove the generated `~/.local/bin/quiet-youtube` launcher if removing the user plugin.

## Protection limits

This is still a browser-filter prototype, not a complete locked child desktop. A child must not have the parent's administrator credentials. The parent password cannot stop an administrator, a modified browser, alternate operating systems, or an unrestricted desktop from bypassing browser policy. User-writable shell plugins and other software in the same session are also not trusted password-entry surfaces against a determined local attacker. The page-context playback guard can be bypassed by arbitrary page JavaScript. The signed package and password service address configuration/removal through the supported controls; the whole-device restrictions and playback boundary need further hardening before treating this as adversary-resistant parental control.

Approving a channel permits future uploads too. This does not assess video suitability, remove ads/sponsorships, or import Google subscriptions. Shorts filtering depends on YouTube metadata.

## Verification

The native tests cover direct API bypass attempts, UID-bound tokens, expiry/revocation, persistence, guessing limits, malformed imports, concurrent channel additions, private CLI sessions, and administrator setup/recovery. Browser fixtures cover filtering and navigation. `scripts/policy-browser.mjs` uses a temporary mount namespace to test real Chromium policy, a real signed CRX, force-install removal restrictions, and live managed-setting changes without altering host policy. That test leaves DevTools enabled inside the namespace so its assertions can inspect Chromium; the shipped deployment disables it.
